# Устройство проекта

```text
src/promptexplorer/
  app.py             — запуск, настройки, журнал, обработка ошибок
  constants.py       — общие константы
  models.py          — модель промта без зависимости от Qt
  metadata.py        — необязательные параметры генерации и проверка JSON
  paths.py           — расположение данных и формат времени
  db.py              — SQLite, транзакции, миграции, импорт и резервные копии
  ui/
    main_window.py   — коллекция, поиск, статистика, экспорт
    image_preview.py — загрузка и отображение миниатюры результата
    prompt_details.py — карточка ресурсов и текстов, раскрытие и копирование
    flow_layout.py   — перенос плашек по ширине карточки
    dialogs/         — выбор профиля и редактирование промта
    utils.py         — оформление, ресурсы и размещение окон
  resources/         — иконки
tests/               — проверки хранения и настоящих виджетов Qt
scripts/             — сборка и снимки демонстрационного интерфейса
docs/                — инструкции разработчика и работа с данными
.github/workflows/   — проверки и сборка артефактов
```

Слой хранения не импортирует Qt. Каждый публичный метод изменения данных открывает
отдельную транзакцию; внутренние вспомогательные методы не вызывают commit.
SQLite проверяет не только существование категории, но и её принадлежность профилю.
Удаление профиля или категории каскадно удаляет зависимые промты.

Версия схемы хранится в `PRAGMA user_version`. База старой версии сначала копируется
через SQLite Backup API, затем преобразуется внутри одной транзакции. Промты сохраняют
идентификаторы и время создания. Идентификаторы категорий могут измениться: общие
категории старой версии распределяются между профилями. Неизвестные поля и потерянные
связи приводят к отмене обновления, а не к удалению данных.

Импорт открывает источник в режиме `mode=ro` и считывает согласованный снимок.
Запись выбранного профиля в целевую базу выполняется целиком либо откатывается.

Версия схемы 2 добавляет необязательный BLOB `prompts.preview`. Переход с версии 1
выполняется через ALTER TABLE с сохранением идентификаторов и резервной копией.
Превью нормализуется в PNG до 512×512 с сохранением пропорций и хранится в той же базе.
Поэтому импорт и резервное копирование переносят картинки без внешних файлов.

Версия схемы 3 добавляет `prompts.metadata` с параметрами генерации в JSON. Значения
сохраняются строками, включая большие seed, чтобы избежать потери точности.
Миграция с версий 1 и 2 выполняется в одной транзакции после резервного копирования.
Текст LoRA не меняется: веса извлекаются только для отображения.

Поиск работает по названию, категории, описанию, Positive, Negative, LoRA и модели.
Используется Unicode casefold, включая кириллицу. Для небольшой локальной коллекции
это проще FTS; на очень больших коллекциях стоит отдельно измерить время поиска
и рассмотреть FTS и постраничную загрузку. Запросы пока выполняются в потоке интерфейса.
